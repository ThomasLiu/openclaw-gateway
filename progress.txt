## 关键 Bug 修复记录

- **connect() resolve bug**: _pendingConnectResolve wrapper 中检查了 !this._connected，
  但 handleMessage 在调用前已设置 _connected=true，导致 resolve 永远不被调用。
  修复：移除 resolve wrapper 中的 _connected 检查，guard 已在 handleMessage 中
  通过 if (result) 确保。
- **chat.send idempotencyKey**: gateway 要求 idempotencyKey 字段，添加 uuidv4() 生成。
- **chat.send message 格式**: gateway 要求 message 为 string 而非 {role, content} 对象。
- **chat.send agentId 参数**: 当 sessionKey 已带 agent: 前缀时，不再发送 agentId 参数
  （gateway 拒绝重复参数 "unexpected property 'agentId'"）。
- **server-only 测试问题**: vi.mock("server-only", () => ({})) 在测试文件顶部拦截导入。
- **EventSource jsdom mock**: ExecApprovalOverlay 使用 EventSource，测试环境需 mock。
- **GET /api/agents 返回格式**: 修复前期望直接返回数组，修复后正确解析
  { defaultId, mainKey, scope, agents: [...] } 格式。
- **OpenClawClient 缺少 logsTail 方法**: gateway 支持 logs.tail RPC，新增 logsTail 方法
  并导出 LogEntry 类型。
- **AgentSidebar props 重复**: 修复 currentAgentId 重复声明导致的 TypeScript 错误。
- **gateway-history.ts extractText**: 修复对 { type: "text", text } 单对象格式的处理。
- **session-unread maxUiMessageId**: 修复数字比较（原按字符串导致 100<50）。
- **inflight-dedupe**: 修复请求结束后再次调用时返回旧 Promise 的 bug（添加 settled 标志）。
- **浏览器端网关连接检查 bug**: ChatApp.tsx 的 checkConnection() 动态导入 getOpenClawClient()，
  该函数依赖 Node.js fs/os 模块，在浏览器中调用失败，导致每次打开应用都显示"网关连接失败"。
  修复：改用 fetch("/api/gateway/status") API 调用，服务端正确读取 ~/.openclaw/openclaw.json。
  截图：verification/01-gateway-fix.png
- **E2E 测试 Playwright 兼容性问题**: E2E 测试因以下原因失败：
  1. `waitUntil: "networkidle"` 无法满足（WebSocket 连接持续活跃）→ 改为 `waitUntil: "domcontentloaded"`
  2. `GatewayAlertDialog` 全屏遮罩（z-50 bg-black/60）拦截点击 → 添加 beforeEach 等待连接完成或关闭遮罩
  3. `[data-testid="composer"]` 不存在 → 改用 `textarea` selector
  4. `text=OpenClaw Gateway` 匹配多个元素 → 添加 `.first()`
  5. 会话列表选择器 `.group.cursor-pointer` 命中 Agent 项而非 Session 项 → 使用 `text=main 会话` 精确匹配
  6. 生产构建 `<main>` 不出现（sessionKey 为 undefined）→ 简化测试逻辑，添加备用选择器
  7. 网关探测超时 12 秒过长 → 减少到 5 秒（PROBE_MS: 12000 → 5000）
